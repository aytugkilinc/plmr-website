What Automation Studio does

One product definition. A connected workflow.

Automation Studio is a working, actively developed application for manufacturers and system owners with configurable outdoor products. It models the dimensions, profiles, options, accessories, calculation and pricing rules that make each company's systems different.

Configure

Define common product settings, enter project dimensions and handle the options or exceptions needed for each position.

Visualise & Prepare

Use project information for 2D drawings, 3D views and the technical documents supported by the agreed product module.

Quote & Handover

Connect company-specific pricing with quotations, product lists and agreed production-preparation outputs.

Company-specific implementation

Your products, rules and outputs.

Start with one product family and representative examples. Agree what the workflow must calculate, show and deliver before expanding it.

Define the product

Supply profile and accessory data, opening arrangements, size limits, options, finishes, motors and the rules or exceptions that affect a configuration.

Agree the outputs

Identify the required drawings, quotations, bill of materials (the list of required parts), cutting or accessory lists, units and export formats. Module and format coverage is confirmed for the implementation.

Review representative cases

Use standard and exception cases to review calculations, pricing and output content. Define delivery, review responsibilities, licensing, maintenance and support arrangements in the scope.

Connected product work

Reuse the project information.

Select a product, establish common settings and add positions. Adjust the exceptions for each position, then use that information for the agreed drawings, quotation and production-preparation outputs.

PLMR can be assessed as a company-specific workflow alongside software you already use. Any exchange with an external system needs its own interface and implementation assessment.

Future development

Build toward the next stages.

The longer-term direction includes broader roof/enclosure coordination, material planning, selected machine or CNC interfaces, packing and dispatch information, and installation or service workflows.

These are development directions. They are scoped separately from the product modules and outputs demonstrated or accepted for a customer implementation.

Technical implementation collaboration

Translate product knowledge into software behavior.

Manufacturers and software providers can request product-rule definition, exception cases, useful input/output specifications and technical implementation support.

A scoped pilot can examine how a configurator represents the physical product and how information passes from sales to technical preparation. The work and deliverables are agreed for the actual product and software environment.
